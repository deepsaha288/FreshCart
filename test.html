What's included

Everything in one platform

From phone OTP login to a full order tracking lifecycle — with admin acceptance, packing alerts, and automated email billing.

👤

User Profile

Name, email, phone. Customers set their email once — it's used for automatic PDF bill delivery. Order history and cart accessible from profile.

✅

Admin Accepts Order

Admin sees new order in panel and clicks "Accept". Customer immediately sees "Request Accepted" on their order screen — no WhatsApp needed.

📦

Packing Done → SMS

When admin marks packing done, an SMS goes to the customer: "Your order is ready — please come pick it up."

📧

Email PDF Cash Memo

Admin clicks "Mark Delivered". System emails the full PDF cash memo (bill) to the customer's registered email address automatically.

🛒

Smart Cart

Price-snapshotted cart. Customer can view cart from their profile. Each item shows price locked at time of adding, not live price.

📊

Admin Panel

3-stage order management: Accept → Pack → Deliver. Revenue dashboard, product management, live order board.

Technology

Full tech stack

Every layer chosen for clarity, fast development, and easy deployment on any server.

Layer Technology Purpose
Frontend Next.js 14 Customer app + Admin panel in one project. App Router, server components, middleware guards /admin routes.
Styling Tailwind + Shadcn/ui Shadcn gives tables, dialogs, badges, toasts for admin. Tailwind for custom screens and mobile layout.
State Zustand Cart items + auth token + user profile state. Lightweight, no boilerplate.
Backend Python FastAPI Async REST API. Auto Swagger docs at /docs. Pydantic validation built-in. Best Python REST choice.
Database ODM Beanie + Motor Async MongoDB ODM. Pydantic models = DB documents. Clean, type-safe.
Database MongoDB (Docker image) mongo:7 Docker container. Replica set enabled for multi-document transactions on checkout.
Auth python-jose + passlib JWT access (15 min) + refresh tokens (30 days). OTP hashed with bcrypt.
OTP / SMS Twilio Verify or 2factor.in OTP on login. SMS to customer when packing done: "Your order is ready — please pick up."
Email (PDF Bill) fastapi-mail + SendGrid When admin marks Delivered → FastAPI emails PDF cash memo to customer's email. PDF attached inline.
PDF Generation WeasyPrint + Jinja2 Jinja2 HTML bill template → WeasyPrint converts to PDF bytes → attached to email.
Images Cloudinary Product images. Free tier 25 GB. CDN included. Direct upload from Next.js browser.
Deployment Docker Compose FastAPI + MongoDB in one compose file. Runs on any Linux VPS. One command: docker compose up -d
Database

MongoDB — Docker image setup

MongoDB runs as a mongo:7 Docker container with replica set enabled — required for checkout transactions. No Atlas dependency, runs on your own server.

docker-compose.yml 
# All services: FastAPI + MongoDB
version: '3.8'

services:

  mongodb:
    image: mongo:7
    container_name: freshcart-mongo
    restart: unless-stopped
    ports:
      - "27017:27017"
    environment:
      MONGO_INITDB_ROOT_USERNAME: admin
      MONGO_INITDB_ROOT_PASSWORD: freshcart123
      MONGO_INITDB_DATABASE: freshcartdb
    command: --replSet rs0 --bind_ip_all
    volumes:
      - mongo_data:/data/db
    healthcheck:
      test: ["CMD","mongosh","--eval","db.adminCommand('ping')"]
      interval: 10s
      retries: 5

  mongo-rs-init:       # runs once, then exits
    image: mongo:7
    depends_on:
      mongodb:
        condition: service_healthy
    restart: no
    command: >
      mongosh --host mongodb
        -u admin -p freshcart123
        --authenticationDatabase admin
        --eval "rs.initiate({
          _id: 'rs0',
          members: [{_id:0,host:'mongodb:27017'}]
        })"

  backend:
    build: ./backend
    container_name: freshcart-api
    restart: unless-stopped
    ports:
      - "8000:8000"
    depends_on:
      mongodb:
        condition: service_healthy
    env_file: ./backend/.env
    volumes:
      - ./backend:/app
    command: >
      uvicorn app.main:app
        --host 0.0.0.0 --port 8000 --reload

volumes:
  mongo_data:
backend/.env

Delivery Roadmap

6-phase development plan

Each phase ends with a working, testable slice of the app — no surprises at the end.

Phase 1 2 weeks
Project Setup + OTP Auth + User Profile
Docker Compose with MongoDB. FastAPI boilerplate + Beanie init. User model (name, phone, email). OTP send/verify via Twilio. JWT tokens. Next.js login page with 6-digit OTP UI. Profile page — name, email, order history, cart, logout.
Phase 2 2 weeks
Products + Cart
Product CRUD API + Cloudinary images. Product listing with category filter + search. Cart API with price snapshots. Cart sidebar with qty controls + totals. Admin product management page. Category management.
Phase 3 1.5 weeks
Checkout → Order Placed → Admin Accept
Checkout API in MongoDB transaction (cart → order + stock decrement). Order confirmation screen. Customer sees "Waiting for acceptance". Admin panel live orders board. "Accept Order" button → updates status → customer in-app notification.
Phase 4 1.5 weeks
Preparing → Packing Done → SMS to Customer
Admin "Mark Packing Done" button. Twilio SMS to customer: "Your order is ready, please come pick it up." Customer app shows "Packing Done — Pick Up Your Order" screen. 5-step status tracker with live polling every 8 seconds.
Phase 5 1.5 weeks
Delivery Done → Email PDF Cash Memo
Jinja2 HTML bill template → WeasyPrint PDF bytes. Admin "Mark as Delivered" button → FastAPI sends email with attached PDF (SendGrid). Customer receives cash memo in inbox. Order history shows past bills for download.
Phase 6 1 week
Polish + QA + Deploy
Input validation, error states, loading skeletons, mobile responsive QA. OTP rate limiting. Admin dashboard stats + revenue reports. Docker Compose production config. Deploy to Linux VPS. Final UAT + handoff.
Total Timeline
9–10 weeks
One developer, full time. Every phase has a working demo you can test before the next begins. FastAPI auto-generates Swagger docs at /docs from day one — no extra API documentation effort needed.
