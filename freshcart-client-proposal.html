Admin Panel

🔄

Live Order Status

Customers see real-time order status updates: Placed → Packing → Ready → Billed. App refreshes automatically.

Database Setup

MongoDB — Docker image

MongoDB runs as a Docker container with a replica set enabled. This unlocks multi-document transactions (needed for the checkout flow) without any cloud dependency.

docker-compose.yml
# Full stack: FastAPI + MongoDB in Docker
version: '3.8'

services:

  mongodb:
    image: mongo:7
    container_name: freshcart-mongo
    restart: unless-stopped
    ports:
      - "27017:27017"
    environment:
      MONGO_INITDB_ROOT_USERNAME: admin
      MONGO_INITDB_ROOT_PASSWORD: freshcart123
      MONGO_INITDB_DATABASE: freshcartdb
    # replica set required for transactions
    command: --replSet rs0 --bind_ip_all
    volumes:
      - mongo_data:/data/db
      - ./mongo-init:/docker-entrypoint-initdb.d
    healthcheck:
      test: ["CMD","mongosh","--eval","db.adminCommand('ping')"]
      interval: 10s
      timeout: 5s
      retries: 5

  mongo-rs-init:
    image: mongo:7
    depends_on:
      mongodb:
        condition: service_healthy
    restart: no
    command: >
      mongosh --host mongodb -u admin
        -p freshcart123 --authenticationDatabase admin
        --eval "rs.initiate({
          _id: 'rs0',
          members: [{_id:0, host:'mongodb:27017'}]
        })"

  backend:
    build: ./backend
    container_name: freshcart-api
    restart: unless-stopped
    ports:
      - "8000:8000"
    depends_on:
      mongodb:
        condition: service_healthy
    env_file: ./backend/.env
    volumes:
      - ./backend:/app
    command: >
      uvicorn app.main:app
        --host 0.0.0.0 --port 8000 --reload

volumes:
  mongo_data: # persists data across restarts
backend/.env
# MongoDB — Docker container
MONGODB_URI=mongodb://admin:freshcart123@mongodb:27017/freshcartdb?authSource=admin&replicaSet=rs0
DB_NAME=freshcartdb

# JWT
JWT_SECRET=your-super-secret-key-change-me
JWT_ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=15
REFRESH_TOKEN_EXPIRE_DAYS=30

# OTP — SMS
TWILIO_ACCOUNT_SID=ACxxxxxxxxxxxxxxxx
TWILIO_AUTH_TOKEN=xxxxxxxxxxxxxxxx
TWILIO_PHONE_NUMBER=+15551234567

# WhatsApp to owner
TWILIO_WHATSAPP_FROM=whatsapp:+14155238886
OWNER_WHATSAPP=whatsapp:+919876543210

# Cloudinary — images + bill PDFs
CLOUDINARY_CLOUD_NAME=your_cloud
CLOUDINARY_API_KEY=your_api_key
CLOUDINARY_API_SECRET=your_secret

# Frontend URL for CORS
ALLOWED_ORIGINS=http://localhost:3000,https://yoursite.com
backend/Dockerfile
FROM python:3.12-slim

# WeasyPrint needs GTK libs
RUN apt-get update && apt-get install -y \
    libpango-1.0-0 libpangoft2-1.0-0 \
    libffi-dev libcairo2 libgdk-pixbuf2.0-0 \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
EXPOSE 8000
CMD ["uvicorn","app.main:app","--host","0.0.0.0","--port","8000"]

Delivery Plan

6-phase roadmap

Each phase delivers a working slice. You can review and test after every phase before the next begins.

Phase 1 2 weeks
Foundation — Project Setup + OTP Auth
FastAPI + MongoDB (Docker) boilerplate. User and OTP collections. TTL index for auto-expiring OTPs. Twilio SMS integration. JWT issue + refresh. Next.js project + Tailwind + Shadcn. Login page with 6-digit OTP UI.
Phase 2 2 weeks
Products + Cart
Product CRUD API. Cloudinary image uploads. Product listing page with category filter + search. Cart API with price snapshot logic. Cart sidebar with totals + quantity controls. Admin: product management page.
Phase 3 1.5 weeks
Checkout → Order → WhatsApp to Owner
Checkout API inside MongoDB transaction (cart → order + stock decrement atomically). WhatsApp item list sent to owner on placement. Order confirmation screen. Live order status polling (every 8s) on customer app.
Phase 4 1.5 weeks
Bill Generation + Customer Notification
Jinja2 bill HTML template. WeasyPrint converts to PDF. Cloudinary upload. PATCH /orders/{id}/ready marks order BILLED, generates bill, sends customer SMS/WhatsApp. Customer sees bill in app + download button.
Phase 5 1.5 weeks
Admin Panel
Live orders board with auto-refresh. Order cards with item lists, status badges, "Packing" and "Send Bill" buttons. Dashboard with today's stats. Product management with add/edit/toggle. Category management.
Phase 6 1 week
Polish + Deploy
Input validation, error handling, loading skeletons, mobile responsiveness. OTP rate limiting (max 3/hour per phone). Docker Compose production config. Deploy to Linux VPS — all services in one compose file. Final QA + handoff.
Total Timeline
9–10 weeks
One developer, full time. Each phase ends with a working, testable deliverable. Phase 1 can begin immediately after project kickoff. FastAPI auto-generates Swagger docs — no extra effort for API documentation.
